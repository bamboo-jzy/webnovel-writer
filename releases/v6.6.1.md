# v6.6.1 - 改了哪一层，系统就帮你检查哪几层

## 发版范围

本次发布覆盖从 `v6.6.0` 到本发布提交的全部变化。主题是**四层方向透传**：总纲 → 卷纲 → 章纲 → 正文 是一条单向链，任一层改动都要检查与相邻层是否同向，并由你裁决改哪一侧；同时补上「卷纲不得改写已落实的章节」。范围 `v6.6.0..v6.6.1`。

## 给作者看的变化

### 改了哪一层，系统就检查哪几层

- 总纲指导卷纲、卷纲指导章纲、章纲指导正文。任一层变化后，系统会采集相邻两层的锚点做一致性检查，列出**候选偏离清单**：
  - `master_to_volume`（总-卷）：总纲 vs 卷纲 —— 卷号存在性、章节范围
  - `volume_to_chapter`（卷-章）：卷纲 vs 章纲 —— 章节目标、涉及实体、伏笔
  - `chapter_to_body`（章-正）：章纲 vs 正文 —— 履约锚点（哪条节拍没写到 / 只写了一半 / 写反了）
- **机器只列候选，不替你拍板**。总纲和卷纲是散文，机器无法做语义等价比对，这两层只输出「差集 + 须你裁决的清单」。每个偏离由你三选一：
  - **改产物**（`align_downstream`）：按依据改下游；
  - **改依据**（`align_upstream`）：调上游。系统会明确告诉你**要上溯到哪一层的哪个单位**，例如「改章纲」要先过卷-章方向检查，再由 `/webnovel-chapter-revise` 改，并继续上溯到卷-章节点；
  - **接受偏离**（`accepted_deviation`）：只记录，不阻断写作。
- 裁决落盘在 `.story-system/handoffs/`，**不改正文、章纲或 commit**。上游一改，此前基于旧快照的结论立即失效，必须重新预览——防止拿着过期结论做决定。

### 每层只允许改「最后一个单位」

| 节点 | 依据 → 产物 | 可改单元 | 既定事实 |
|---|---|---|---|
| `master_to_volume` | 总纲 → 卷纲 | 最后一卷 | 其余已规划卷 |
| `volume_to_chapter` | 卷纲 → 章纲 | 最后一章 | 其余已规划章 |
| `chapter_to_body` | 章纲 → 正文 | 最后一章正文 | 其余已有正文章 |

- 最后一行是**代码级阻断**，不只是提示词：`/webnovel-chapter-reload` 在目标章不是最后一章时报 `handoff_target_locked`（`--backup-only` 豁免，纯备份不受限）。
- 理由：前面的章已是既成事实，倒着改会让「哪一版是准的」无法回答。要改只能回退到那一章重写。

### 卷纲不再能碰已落实的章节

- 重写卷纲时（人工改后 `/webnovel-volume-reload`，或 `/webnovel-volume-revise`），章号会被划成**锁定区**（已有章纲或正文）与**可改区**（尚无章纲）。锁定区的章纲与正文**本次零改动**，报告直接告诉你是哪几章、范围多少。
- `/webnovel-chapter-plan` 遇到已有章纲或正文的章**一律跳过**，不留「用户要求即可覆盖」的口子——否则锁定区可以从下游被绕过。
- 卷纲里已被章纲落实的内容（节拍、时间锚点、倒计时、角色状态、伏笔推进、章级承接）不可再改；这类诉求会转为改对应章纲。

### 顺手修的

- `/webnovel-write` 的弃稿说明此前残留 v6.6.0 之前的旧口径（`git switch -c rewrite-from-*`），照它手工操作会另开分支；已改成原地回退口径。
- 新增「改完章纲想重新生成正文」的分流说明：草稿章先刷合同再重跑；已 accepted 章必须先 discard 再改章纲（回退是整树还原，顺序反了会把章纲改动一起退掉）。

## 是否需要改旧项目

不需要。

- 方向裁决记录写在 `.story-system/handoffs/`，旧项目不会凭空多出文件。它与 `reconciliations/`（章内履约对账）分工不同：前者管**层间方向**，后者管**章内节点有没有写到**，互补而不互相替代。
- 卷纲重载新增的锁定区报告只是新增字段，旧项目下次重载自然就有。

## 适合谁升级

- 所有用户。特别是改过卷纲、又担心「下游章纲会不会被悄悄改掉」的人——现在有明确边界和逐章报告。
- 想要「改动有据可查」的人：每次层间裁决都留档，谁改的、什么理由、影响了哪些章，都写进 `.story-system/handoffs/`。

## 已知影响

- **非最后一章的正文不再有重载入口**（本次最需要注意的变化）。倒数第二章之前任意一章的正文，从前可以人工改写后 `/webnovel-chapter-reload` 重载；现在会被 `handoff_target_locked` 阻断，**连改错别字也不行**。要改只能从那一章起整条尾巴按章序回退重写。`--backup-only` 不受影响。这是「每层只能改最后一个单位」的直接代价，已写进 `/webnovel-chapter-reload` 的命令文档和 `/webnovel-write` 的失败恢复段。
- **规划与改纲多一步检查**：每次卷纲 / 章纲 / 正文改动前会多一次方向检查，检查与裁决是分离的两步，慢一点，换来来源可追溯。刻意的取舍。
- **总纲与卷纲的一致性只做到「锚点级」**：卷号存在性、章节范围这类可机械比对的项会被报出；卷名、核心冲突、卷末高潮等散文项一律列为「须作者裁决」。这是能力边界，不是未完成项。
- **章-正节点沿用了旧术语**：`outline_to_body` / `body_to_outline` 是 `align_downstream` / `align_upstream` 的别名，已有记录不受影响。

## 给维护者

### 新增 `direction_handoff.py`（838 行）

- 三节点常量 `HANDOFF_NODES`、裁决值 `HANDOFF_DECISIONS`、别名表 `DECISION_ALIASES`（`outline_to_body` → `align_downstream`，`body_to_outline` → `align_upstream`），`normalize_decision()` 做归一。
- `describe_handoff_scope()` 划「可改单元 / 既定事实」；`check_handoff()` 采集锚点输出候选偏离；`record_handoff()` 落盘并校验 `input_token` / `reason` / `impact` / 目标锁定；`body_edit_boundary()` 是代码级末端约束。
- `_upstream_target()` 做单位换算：`volume_to_chapter` 上溯到 `master_to_volume` 时把**章号换成所属卷号**（否则会把章号当卷号交给 `/webnovel-outline-revise`）。
- `_binding_digest()` 绑定「边界快照 + 上游来源 + 候选偏离」的 SHA-256 作为 `input_token`，上游一改即失效。
- 尚未生成的单位不算锁定：target 不在已存在集合时给 `target_allowed=True` + `target_pending=True`，并在 `scope_declaration` 里说明。
