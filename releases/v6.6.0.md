# v6.6.0 - 卷纲、章纲先和你讨论再生成

## 发版范围

本次发布覆盖从 `v6.5.0` 到本发布提交的全部变化。两个主题：**规划阶段先讨论后生成**（卷纲 / 章纲，含各自的修改流程），以及**抛弃章节不再新建分支**。范围 `v6.5.0..v6.6.0`。

## 给作者看的变化

### 规划不再由 AI 一个人拍

- `/webnovel-plan` 生成卷纲前，会先和你把**10 项卷级决策**逐轮过一遍（卷核心冲突、卷末高潮与承接、中段反转、危机递增、时间体系、倒计时、伏笔埋收、新增设定边界等）。每轮只问 3-5 个议题，先给出建议、理由和风险，再给有限选项，你选一个或说你的想法即可。
- `/webnovel-chapter-plan` 同样先讨论，但**按批次走**：第一批问全 10 项章级议题（批次切分、节拍节点落章、每章目标、阻力与代价、承接链、时间锚点、倒计时节奏、伏笔、爽点分布、本批禁区），后续批次只问还没定的和与卷纲有偏离的，不会每批都从头问一遍。
- 讨论结论会落成一份**决策卡**（卷纲 `大纲/第N卷-规划讨论.md`、章纲 `大纲/第N卷-章纲规划讨论.md`），你随时能看到"这一卷/这一批到底定了什么、是谁定的"。中断了也能接着聊，不必从头开始。
- **没有轮次上限**，但每一轮都带「不再讨论，结束对话」这个选项。你选它，对话就结束。不想一项项聊，也可以直接说"按你的建议来"——系统会把建议记成"作者明确接受默认"，照样通过。
- 讨论没过闸门（决策卡为空、10 项还有未决、存在 `BLOCKER`、或你尚未确认）时，**不会落下任何卷级 / 章级产物**：不写节拍表、不写章纲、不刷合同、不动状态。只保留决策卡，并告诉你卡在哪、怎么恢复。
- 修改流程口径一致：`/webnovel-volume-revise` 与 `/webnovel-chapter-revise` 的确认轮同样**无次数上限**，每轮同样带「不再讨论，按当前已确认范围结束」。

### 抛弃章节：不再建分支

- 已定稿的章被抛弃时，以前会新建一个 `rewrite-from-chXXXX` 分支并切过去。现在改为**原地回退**：工作树和索引恢复成"上一章完成时"的样子，然后在**当前分支**追加一次「抛弃第 N 章」提交。HEAD 不换分支，你不用再记自己在哪条线上。
- 被抛弃的提交**一条都没删**——它成为新提交的父提交，仍在这条历史里；版本点 tag `chN` 也不移动。想看一眼丢掉的正文，照旧 `git show chN:正文/第N章-*.md`。
- 顺带修掉一个老麻烦：**同一个章反复抛弃不再被卡住**。旧实现在第二次抛弃时会因为"同名分支已存在"直接阻断，现在没有这个副作用了。
- 草稿章那条路（归档到 `.webnovel/discarded/` 后删除）没变，本来就不碰 git。

## 是否需要改旧项目

不需要。书项目数据无需迁移：

- 两份讨论稿是新增的**可选**产物，旧项目不会凭空多出文件；下次跑 `/webnovel-plan` 或 `/webnovel-chapter-plan` 时才会生成。
- 决策卡放在 `大纲/` 下，因此**会自动进入版本点备份**，和你的大纲、设定一起被保住。
- 弃稿改的是执行方式，不涉及数据结构；已有项目的历史、版本点 tag、`.webnovel/` 状态原样可用。

## 适合谁升级

- 所有用户。尤其是觉得"卷纲/章纲像 AI 自己拍的、改起来不知从何下手"的人——这次改的就是这一点。
- 用过 `/webnovel-chapter-discard` 的人：分支管理的心理负担可以直接忘掉。

## 已知影响

- **规划会变慢一点**：卷纲第一次规划会多出讨论环节，时间长了，换来的是产物来源可追溯。这是刻意的取舍。
- **没有跳过讨论的开关**（刻意不提供 `--skip-dialogue`）。留开关等于闸门失效；要快就说"按你的建议来"。
- **决策卡里不能写占位标记**：`[待...]`、`（暂名）`、`{占位}` 一律不要写，未决统一写 `待定`。原因是 `大纲/` 下所有 Markdown 都会被写前门禁扫描，讨论稿里的占位符会变成阻断正文写作的假 blocker。这条已写进 SKILL.md 的硬规则。
- **弃稿的提交历史形态变了**：旧版不新增提交、另开分支；新版在**当前分支**留一次「抛弃第 N 章」提交。历史依旧完整可取回，但如果你有脚本按"抛弃后分支名"判断状态，需要跟着改。

- `scripts/data_modules/chapter_discard.py`：删 `ROLLBACK_BRANCH_PREFIX` / `INITIAL_ROLLBACK_BRANCH`，改为 `ROLLBACK_MODE = "in_place"`。`_rollback_probe` 去掉 `branch_name` / `branch_exists` / `rollback_branch_exists`，新增 `mode` / `creates_branch=False` / `commit_message` / 按 tag 实际存在情况生成的 `recovery_hint`，以及新阻断 `version_point_not_ancestor`（`git merge-base --is-ancestor`，防止把两段不相关历史拼起来回退）。
- `rollback_chapter` 新链路：归档正文与 commit 到 `.webnovel/discarded/` → `git read-tree -u --reset <版本点>` → 有差异才 `git commit -m "Discard chapter N: restore to <版本点>"` → 核对改为 `tree_matches_target`（`git diff --quiet <target> HEAD`）+ `chapter_body_absent` + `current_chapter_after`。
- 选 `read-tree -u --reset` 而非 `git reset --hard`：后者被 `evals/fixtures/behavior/fast.json` 的 `forbidden_patterns` 明确禁止，且会移动分支指针（等于改写历史）；`read-tree` 只改工作树与索引，未跟踪文件（含归档目录）保留。`git switch --detach` 因留 detached HEAD 隐患被弃用。
- `scripts/data_modules/webnovel.py`：`--rollback` 帮助文本同步。
