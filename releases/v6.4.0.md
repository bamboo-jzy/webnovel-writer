# v6.4.0 - 一章不要了，直接抛弃

## 发版范围

本次发布覆盖从 `v6.3.0` 到本发布提交的全部变化：新增「抛弃正文」能力，让「这一章写崩了、整章不要了」第一次有正规入口。范围 `v6.3.0..v6.4.0`。

## 给作者看的变化

### 新增：抛弃正文（`/webnovel-chapter-discard`）

- **一章不要了，直接抛弃**。以前只能自己敲 git 命令，现在按这一章的状态自动选路：
  - **还没定稿**的章（只有正文和草稿）：整章归档到 `.webnovel/discarded/chapter_NNN_<时间戳>/` 后删除，连同这一章的审查报告一起清掉；**章纲保留**，重写就行。
  - **已经定稿**的章：走版本点回退，整棵树回到上一章完成时的状态。
- **回退不删除任何提交**。原分支仍指向被你抛弃的那次提交，随时可以用 `git show <原分支>:正文/第N章-xxx.md` 取回核对——"抛弃"是搬家，不是销毁。
- **只允许抛弃最后一章**。抛弃中间章会让后面的章失去前置章，系统会直接拦下并说明原因，而不是删完才发现序列断了洞。
- **抛弃前一律先预览**：会告出这一章现在是什么状态、能走哪条路、会动哪些文件、哪些文件保留；确认后才执行。工作区有未提交改动时，回退会被拦下，不会顺手把你的改动一起丢掉。
- **第 1 章也能抛弃**：没有 `ch0000` 版本点时，自动回退到仓库初始提交（分支名 `rewrite-from-start`）。

### 抛弃之后怎么接着写

- 回退后你处在「第 N-1 章完成后」的状态，**要写的下一章仍是第 N 章**，章纲没被动过，直接重写这一章即可。
- 草稿删除后，`state.json` 的进度、本章元数据、审查检查点会一并清掉，`chapters_planned` 回到「待写」；不会出现"正文没了但进度还记着"的状态。

## 是否需要改旧项目

不需要。已有书项目继续使用，无需迁移 `.story-system/` 或 `.webnovel/` 数据。

`.webnovel/discarded/` 是新增的**按需创建**目录：从没抛弃过章的旧项目不会出现它，它也不进版本点（归档副本留在原地，不随 Git 提交）。

行为习惯上只有一点新增：弃稿现在有了正式命令，写章失败恢复的文档也改为指向它（原先只给手工 git 命令）。

## 适合谁升级

- 正在连载、经常遇到「这一章方向写偏了，整章不想要」的作者。
- 以前靠手工敲 `git switch -c` 回退、担心敲错分支或丢掉提交的作者。
- 只想删掉当天没定稿的草稿、不想碰 git 的作者。

## 已知影响

- 已定稿章的回退是**整棵树回退**（正文、`.story-system/`、state、索引、投影日志一起回），不是只删一章的正文。这是刻意设计：`state.json` 的 `plot_threads` / `strand_tracker` / `protagonist_state` 是累计字段，索引里的 `entities.first_appearance` / `last_appearance` 也不随撤回回退——只删正文和部分投影行，会留下一本"读模型说没写过、状态记得写过"的书。
- 回退要求工作区干净。有未提交改动时先提交或自行处理，系统不会替你丢弃改动。
- 被抛弃的提交仍在仓库里，因此**仓库体积不会因此变小**；需要彻底删除请自行 `git gc` 前先确认不再需要。
