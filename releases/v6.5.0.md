# v6.5.0 - 最低 Python 版本提升到 3.12

## 发版范围

本次发布覆盖从 `v6.4.0` 到本发布提交的全部变化，主题是**运行环境门槛**：插件与脚本的最低 Python 版本从 3.10 提升到 3.12，并补齐 CI 里长期缺失的验证环节。范围 `v6.4.0..v6.5.0`。

## 给作者看的变化

### 需要 Python 3.12 或更高

- 插件及其脚本现在要求 **Python 3.12+**。3.10 / 3.11 不再支持，也不再进入测试矩阵。
- 如果你还在 3.10 / 3.11，**请先升级 Python 再升级插件**。低于 3.12 时 `doctor` 会直接报 blocker（`python.version`），并用中文说明「切换到 Python 3.12 或更高版本」，而不是让你在别处以一堆看不懂的报错收场。
- 你的正文、大纲、设定集**一个字都不用改**；这一步只影响运行插件的 Python 环境。

### 安装指令改为从本仓库安装

- `README.md` 与 `webnovel-writer/README.md` 里的安装命令，从 `lingfengQAQ/webnovel-writer` 改为 `bamboo-jzy/webnovel-writer`（`claude plugin marketplace add` 与 `pip install -r` 两处）。
- `plugin.json` / `marketplace.json` 里的作者署名与项目主页**没有改**，仍指向上游——那是署名与项目主页，不是安装源。

## 是否需要改旧项目

不需要。书项目数据无需迁移；`.story-system/`、`.webnovel/` 保持原样。

唯一的动作是**确认运行插件的 Python ≥ 3.12**。用 `python -V` 看一下即可；低于 3.12 时先升级 Python，再照常打开你的书项目。

## 适合谁升级

- 所有用户（这是环境要求变更）。已经在用 3.12+ 的人只需升级即可，写作体验无变化。
- 手上还有 Python 3.10 / 3.11 环境的人：先升级 Python 再升级插件，否则 `doctor` 会拦下。

## 已知影响

- **破坏性变更**：3.10 / 3.11 环境升级后会直接得到 blocker，无法继续工作，直到升级 Python。这是刻意的——与其在旧解释器上以奇怪的方式偶发失败，不如一开始就说清楚。
- 之前「声明支持 3.10，但 CI 从未跑通 3.10/3.11」的状态终结：现在声明的最低版本就是实际被测的版本。
- Windows 侧 `run_tests.ps1` 的预检失败信息仍被 `2>$null` 丢弃，属于维护者的已知遗留问题，不影响作者使用。

## 给维护者

- 根因：`scripts/conftest.py` 的 `_SafeTemporaryDirectory` 把 **Python 3.12 才引入的 `delete=`** 参数透传给 `tempfile.TemporaryDirectory` → 3.10/3.11 上每次实例化即 `TypeError: unexpected keyword argument 'delete'`。该安装发生在模块导入期，因此 pytest **还没跑用例**就在收集阶段炸掉 37 个测试模块，整轮以 `exit code 2`（Interrupted）中断——这正是 `Python Test Matrix` 长期红、且与「要求 3.10+」声明相矛盾的根源。
- 真机复核（NuGet 下载 CPython 3.11.9，`scripts/conftest.py` 前后替换）：修复前 `Interrupted: 37 errors during collection` / `543 collected` / `EXIT=2`；修复后 `1012 collected` / `EXIT=0`。3.14.5 上修复后同样 `1012 collected` / `EXIT=0`。故障注入实验（3.13 上伪造 3.11 同款行为）得到完全一致的 `37 errors` + `EXIT=2`。
- 处置：最低版本提升到 3.12 后该缺陷不出现在受支持版本上；`conftest.py` 仍保留 `_TEMPDIR_SUPPORTS_DELETE = sys.version_info >= (3, 12)` 门控，使旧解释器上至少不会以「收集中断」的怪形态失败，便于诊断。
- 测试矩阵 `.github/workflows/test-matrix.yml`：`python` 由 `['3.10','3.11','3.12']` 改为 **`['3.12','3.13','3.14']`**（Ubuntu + Windows 共 6 个 job），删除 `exclude: windows + 3.10`。
- **新增独立 job `quality`**（Ubuntu + 3.12）：把 `run_behavior_evals.py` 与 `validate_plugin_package.py` 从矩阵 job 拆出。原先这两步的 `if` 条件是 `ubuntu-latest + Python 3.11`，而该 job 在更早的 pytest 步就失败 → 它们在 CI 里**从未真正执行过**，skill 契约评测与插件包校验长期零兜底。
- 版本声明同步：`scripts/requirements.txt`（`# Python >= 3.12 required`）、`README.md` 徽章（`Python-3.12+`）、`docs/operations/operations.md` 的 CI 覆盖描述。运行时门控收敛到 `doctor.py` 的 `_MIN_PYTHON = (3, 12)` 一处，不再散落 5 个 `(3, 10)` 字面量。
- `plugin-release.yml` 与 `plugin-version.yml` 自身使用的解释器由 3.11 升到 3.12。
- 安装源改动：`README.md`（2 处）与 `webnovel-writer/README.md`（1 处）的 `lingfengQAQ` → `bamboo-jzy`。本仓库是 `lingfengQAQ/webnovel-writer` 的 fork（GitHub API `fork: true`），署名与 `homepage` / `repository` 字段保持指向上游不动。
- 已知未处理：Windows 侧 `run_tests.ps1` 的临时目录预检失败时 stderr 被 `2>$null` 丢弃 → `exit code 1` 无法区分「预检失败」与「用例失败」。修法（去掉 `2>$null`、显式解释器、预检加超时）已记入 `docs/operations/`，本次未改。

## 验证

- 真机 3.11.9：`Interrupted: 37 errors during collection` / `543 collected` / `EXIT=2`（修复前）→ `1012 tests collected in 4.09s` / `EXIT=0`（修复后）。
- 真机 3.14.5：全量 `--collect-only` → **1012 tests collected in 3.64s / EXIT=0**；`test_validate_release_notes.py` + `test_prompt_integrity.py` → **145 passed in 3.67s**；`test_doctor.py` + `test_validate_plugin_package.py` + `test_validate_release_notes.py` → **22 passed**。
- `doctor._python_checks()` 实测：3.14.5 → `status ok` / `expected ">= 3.12"`；3.11.9 → `status error` / `severity blocker` / repair「切换到 Python 3.12 或更高版本。」
- 行为评测 `run_behavior_evals.py`：**25/25 PASS**；`validate_plugin_package.py`：**0 error 0 warning**。
- 三个 workflow YAML 解析通过（jobs：`pytest` / `quality` / `release` / `check`）。
- `python -X utf8 webnovel-writer/scripts/sync_plugin_version.py --check --expected-version 6.5.0`
- `python -X utf8 webnovel-writer/scripts/validate_release_notes.py --version 6.5.0`
- `python -X utf8 webnovel-writer/scripts/validate_plugin_package.py`
- `git diff --check`
- 未跑全量 pytest：本机在含 git/subprocess 的用例上约 40s/用例，全量需数小时；本次改动面为 CI 配置、版本声明、`conftest.py` 门控与文档，已用真机 collect 自检覆盖。
