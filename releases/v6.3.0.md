# v6.3.0 - 文风有档案，漏章藏不住，已定稿的事实也能改

## 发版范围

本次发布覆盖从 `v6.2.1` 到本发布提交的全部变化，是 v6 线上的一次大版本：新增「文风档案」能力，补齐「索引对账」与「事实改写」两条闭环，并收敛单书工作区规约。

## 给作者看的变化

### 新增：文风档案（`/webnovel-style-learn`）

- **「文风」第一次变成一份可复用的档案**。它同时看两处：从 `正文/` 学你**已经写成什么样**（只统计已提交接收的章节，未定稿的草稿不算数），从 `文风/` 学你**想写成什么样**（把要模仿的参考文本片段放进去即可）。
- 档案给出**现状**、**目标**、两者**差异**，外加两条硬约束检查（长句占比、said tag 占比）。摘要会自动进写章任务书，起草时就能看到「你的老习惯」和「你这次想往哪走」。
- **现状与目标永远分开，现状不会自动升级成「标准」**；两者冲突时以目标为准。这一点是刻意设计的——否则写着写着，自己的惯性就变成了评判标准。
- `文风/` 目录随版本点一起备份，参考文本不会丢。建议只放要模仿的片段，不要放整本书。
- **配套变化：文体体检的参照物换成「这本书的既定文风」**。`/webnovel-audit` 的 S5（句长 / 对话占比漂移）以前是拿「这次扫的那一段」自己当中位数——只扫一卷时基线就是那一卷，同一章换个范围扫描结论会不一样，跨卷没法比。现在默认改用档案里的全书画像当基线，**跨卷可比**；报告会写明这次用的是哪种基线、来自多少章、档案生成于何时，档案比正文旧时会提示重建。想恢复旧口径用 `--baseline range`。
- **删掉了没人用的「风格采样」模块**（`webnovel.py style`）。它的存储一直是 0 条、没人调用，能力已由文风档案承担；留着两套实现只会误导后来者。`webnovel style ...` 现在会直接报参数错误。
- dashboard 的「文档浏览」现在也能看 `文风/`（只读）。

### 索引与提交：不再「看起来成功」

- **索引漏章现在会被发现**。`/webnovel-doctor` 会拿索引库和章节提交对账：如果 `.webnovel/index.db` 被清理脚本删过、被覆盖成空库，或某一章在索引里消失（以前**一律报「正常」**），现在会明确报出缺了哪几章，并给出可直接复制的重建命令（`projections replay`）。
- **提交成功但索引没写成功时不再「看起来成功」**。写章提交在索引写入失败（例如库只读）时会返回失败，并告诉你是哪一项失败、怎么补跑；正文与提交事实都还在，不需要重写。
- **索引库被别的程序占用时不再几秒就失败**：默认等 30 秒，短暂占用会自动等过去（同时开两个终端或 dashboard 时很常见）。
- 投影被旧数据挡住、半途写坏时，补跑入口升级为 `projections retry --chapter N --retract`（先撤回该章派生数据再重放）。
- 同一章里场景序号重复（例如两个场景都写 1）不再让该章索引投影整章失败，系统会顺延序号并在日志里说明。
- 以 `第7章-标题.md` 这种不补零的文件名保存正文时，体检会提示改名（只提示，不阻断写章）。

### 已定稿的事实也能改（默认仍然拦截）

- 以前某章一旦提交，再改写事实会被安全拦下（提示「增量投影撤不掉旧事实」），只能绕过系统。现在确认后用 `chapter-commit --allow-fact-revision --revision-reason "..."` 即可：系统先撤回该章的派生数据（索引行、向量分块、事件镜像）再整章重建，旧版本自动进历史。
- **默认仍然拦截**，不会误改；拦截时会直接把当前版本标识和该加的开关一起打给你。

### 单书工作区

- **一个工作区一本书**。书目录可以直接就是工作区根，也可以是工作区下唯一的书目录。工作区里放了两本书时，命令会明确告诉你「检测到 2 本书、无法判定」，并列出书单和处理方式，不再含糊地说「这里不是项目」。
- 往已有书的工作区里再初始化一本新书时，会收到醒目提示：该工作区已有一本书、建议新书另建工作区；同时告知工作区指针已改绑到新书（以前这一步没有任何提示）。

### 其他

- 恢复到历史版本改用 git 原生命令 `git switch -c rewrite-from-chXXXX chXXXX`。插件不再提供内置回退命令，也不再写「回退到某个章节快照」的文档承诺。
- 章节改完之后如果重新备份，恢复点能正确定位到当前版本（原先「改正文 / 改章纲后重跑备份」会直接失败）。
- embedding 服务限制单请求条数时，向量化会自动缩小批次重试（不再「整章 0 条写入」），单批条数可用 `EMBED_BATCH_SIZE` 调整。
- 老项目迁移入口移除：本系统面向新建项目，不再提供从 v5 老数据结构搬运数据的命令。

## 是否需要改旧项目

不需要。已有书项目继续使用，无需迁移 `.story-system/` 或 `.webnovel/` 数据。

`文风/` 是新增的**可选**目录：老项目不建也不影响任何命令（备份会自动跳过不存在的路径，写章任务书里也不会多出文风段），首次跑 `/webnovel-style-learn build` 时会自动创建；`init` 新建的项目会预建该目录。

注意两点行为变化：① 一个工作区里放多本书不再被支持，请把每本书放在自己的工作区；② 原 `migrate` 子命令已移除。

升级后第一次 `/webnovel-doctor` 若报索引缺章，说明这个漏章**在升级前就已存在**（只是当时没有任何检查能发现），按提示的 `projections replay` 修一次即可。

## 适合谁升级

- 所有在写长篇连载的作者：文风档案、索引对账、事实改写都是日常会用到的能力。
- 曾经遇到过「体检查不出漏章」「改了一句话就被拦」「重跑备份失败」的作者：这版正是针对这些场景。
- 只有一个工作区、一本书的写作者：升级无成本，无需任何调整。

## 已知影响

- S5 的偏离结论默认改看档案基线。若你还没建档案，行为与以前一致（回落到本次扫描范围的中位数），只是报告里会多一行说明；想显式回到旧口径用 `--baseline range`。
- 索引重建（`projections replay`）是重操作，首次对老项目补齐时可能需要几十秒，属正常。
- 参考文本放进 `文风/` 后会随 Git 版本点一起提交，体积与版权由作者自己把握——建议只放片段。
