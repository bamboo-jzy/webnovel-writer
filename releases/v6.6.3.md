# v6.6.3 - 弃稿回退精确到「正文还没写」那一刻

## 发版范围

本次发布覆盖从 `v6.6.2` 到本发布提交的全部变化。主题是**把「抛弃一章正文」的回退终点做准**：新增写前点 `backup --prewrite`，并让 `/webnovel-chapter-discard` 在回退时保留本章的章纲与章级合同。范围 `v6.6.2..v6.6.3`。

## 给作者看的变化

### 抛弃正文后，章纲一定还在

以前 `/webnovel-chapter-discard` 回退到上一章版本点 `ch{N-1}`，而那一刻**通常还没有本章的章纲**——章纲写于本章规划期，晚于 `ch{N-1}`。结果是：抛弃正文把章纲一起带走了，`SKILL.md` 里写着「章纲保留」但实现做不到。

现在回退会**先把本章的章纲与章级合同取出来，回退之后再写回并纳入本次「抛弃」提交**：

- 独立章纲 `大纲/第N章-*.md`、以及章纲落在卷级详细大纲时的 `大纲/第N卷-详细大纲.md`（`legacy_volume` 落盘）；
- 章级合同 `.story-system/chapters/chapter_00N.json` 与审查记录 `.story-system/reviews/chapter_00N.review.json`。

**回退终点固定是「正文没了、但章纲还在」**，抛弃之后可以直接 `/webnovel-chapter-revise N` 改章纲重写，不必从零重建。

报告新增三个字段，且**都参与 `ok` 判定**：`planning_preserved`（写回了什么）、`planning_artifacts_present`、`missing_after_rollback`。章纲写回失败不会再以 `ok=true` 蒙混过去。

### 写前点：回退终点回到「这一章还没动笔」

上一节解决了章纲，但回退到 `ch{N-1}` 仍会丢掉**写这一章期间顺手做的其它改动**（补的设定集条目、微调的第 1 章大纲……）。`v6.6.3` 新增写前点解决它。

`/webnovel-write` 在**正文落笔之前**（Step 1 之前）自动打一个 tag `pre-ch{NNNN}`：

```bash
python -X utf8 "${SCRIPTS_DIR}/webnovel.py" --project-root "${PROJECT_ROOT}" backup \
  --prewrite \
  --chapter {chapter_num} \
  --chapter-title "{title}"
```

此后再 `/webnovel-chapter-discard N`，回退目标按 **写前点 `pre-ch{N}` → 上一章版本点 `ch{N-1}` → 仓库初始提交** 依次选取。命中写前点时，工作树精确回到「本章正文一行都还没写」的状态：章纲在、章级合同在、写这一章期间改的设定集与大纲也都在。

三条细节：

- **写前点与版本点分属两个命名空间**：`pre-chNNNN` 不参与 `verified_backup`、不计入版本点统计、不写 `backup_receipts.json`。`backup --list` 会把写前点单列一段，不混进章节版本点。
- **打点失败不阻断写作**：命令返回非 0 时如实记进过程提示、继续写。缺写前点只是让回退退回 `ch{N-1}` 并走章纲写回兜底，不会让你写不下去。
- **同章重写会前移写前点**，旧点保留为 `pre-ch{NNNN}-prev-<时间戳>`。

### 一处要理解的取舍

写前点的语义是「撤销写这一章期间发生的一切」——包括**顺手改的其它章大纲、顺手补的设定集**。也就是说 `/webnovel-chapter-discard` 的作用粒度是**「一个写作动作」**，不是「这一章的文件」。如果你希望保留写这一章期间的附带改动，回退后手工取回即可（`git show HEAD^:<路径>`）。

## 是否需要改旧项目

不需要，也不强制。老项目里没有 `pre-chNNNN` 写前点，`chapter-discard` 会自动退回 `ch{N-1}` 并走章纲写回兜底，行为与本次升级前的预期一致，只是现在**章纲真的会被保住**。

想用上写前点，只需在下次 `/webnovel-write` 时让流程正常打点即可；手工写作、或从中间章开始的项目，不补写前点也能跑。

## 适合谁升级

- 抛弃过正文、发现章纲被一起带走的人：本次修的就是这个。
- 想「改章纲重写正文」的人：回退终点现在精确到「正文没动笔」，改完章纲即可重写。
- 使用 6.6.1 或更早版本的人：本次一并带上 `v6.6.2` 的非末章正文硬约束与 `v6.6.1` 的四层方向透传。

## 给维护者

### 写前点

- `scripts/backup_manager.py`：新增 `prewrite_point_tag()` / `prewrite_point()` / `prewrite_point_commit()`；把 `backup()` 里的「解析 HEAD → 落 tag（含前移归档）」抽成 `_snapshot_commit()` 与 `_place_point_tag()` 供版本点与写前点共用，`backup()` 对外行为不变。
- 命名规则用 `_PREWRITE_TAG_PREFIX = "pre-ch"` + `_PREWRITE_TAG_PATTERN = ^pre-ch(\d{4})$`：既不匹配版本点的 `^ch(\d{4})$`，也不匹配 `git tag -l "ch*"`，因此 `verified_backup`、版本点统计、历史点解析零污染。
- `list_backups` 单列写前点段（`tag -l "pre-ch*"`）；写前点不写 `backup_receipts.json`。
- CLI 新增 `--prewrite` 开关（配合 `--chapter` / `--chapter-title`）。

### 回退目标与规划产物

- `scripts/data_modules/chapter_discard.py`：`_plan_rollback` 的 target 选取顺序改为 **写前点 → `ch{N-1}` → 初始提交**，报告新增 `target_kind` / `prewrite_point_tag` / `prewrite_point_exists` / `prewrite_point_commit`。
- 新增 `planned_artifact_paths(root, chapter)`：覆盖 `split` 独立章纲与 `legacy_volume` 卷级详细大纲两种落盘，外加章级合同与审查记录。
- `rollback_chapter` 流程：归档 → 取出规划产物 → `git read-tree -u --reset {target}` → 核对（**写回之前**）→ 写回并 add → 追加「抛弃第 N 章」提交。
- `tree_matches_target` 的语义因此变为「写回产物**之前**」核对：新提交 = 版本点 + 保留产物，不再逐字等于 target。测试辅助 `_assert_worktree_restored` 的判据同步从树级改为 **blob 级**。
- 写前点模式下即使工作树与 target 完全一致，也用 `--allow-empty` 保证留下「抛弃」提交。
- 新增阻断 `version_point_not_ancestor`：回退目标必须是当前提交的祖先，防止跨分支误操作。
